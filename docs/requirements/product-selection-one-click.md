# PR1：选产品，一键生成营销方案

## 用户需求与优先级

2026-10-18 用户明确提出：当前需要自己创建营销任务、手动输入产品和大量内容，不符合“一键生成营销方案”；希望把资料库的产品和图片放进界面，让营销员选择产品，尽量使用选项并减少输入。

本需求是当前主流程的产品调整，优先于旧文档中“先填产品、人群、场景、目标，再逐阶段手工确认”的交互要求。职责分工不变。当前用户请求未要求修改线上事实来源原则，产品与图片继续来自线上 IMA 共享库；本地资料不直接成为运行时数据源。
本文件定义产品行为与分工，不声称功能已实现，也不擅自将下列概念字段或能力名称当成已冻结 HTTP API。Coordinator 结合现有 §8 契约收口最小增量接口。

## 默认体验

已登录用户：打开产品选择页 → 点击一张明确型号的产品卡片 → 点击“一键生成营销方案” → 查看完整初稿与核验结果。

- 正常路径不要求填写任何文本，也不需要先给任务命名。系统自动创建、命名并保存任务，任务列表作为历史记录。
- 产品卡片展示真实产品图、完整型号/版本及必要的资料状态。展示证据支持的简介即可，不凑卖点、价格、配置或评价。
- 型号版本不同的产品需明确区分；用户点选明确版本的卡片即完成产品选择，不再要求重复输入型号。
- 提供可选的搜索/筛选；浏览产品时无需先输入关键词。第一屏优先展示当前已核实可用的产品，逐步扩展到库中其他真实产品，不把单型号实现伪装成全库目录。
- 默认采用“系统推荐方案”。平台先推荐已有实现的小红书；用户可点选公众号。目标默认“引导到店体验”。这些是可调整的产品默认值，不是用户提供的事实。
- 人群、场景、卖点与策略由 Workflow 根据真实证据自动建议；点击生成后连续完成证据读取、画像/策略建议、平台内容和核验，不要求用户每步点击确认。
- 展示处理进度、结果和推荐依据。推荐画像/策略应标明“系统推荐”，不能伪记成“用户已确认”；初稿生成不等于通过核验或可直接发布。
- 结果页支持“换人群”“换平台”“调整目标”“重新生成”。用户通过选项修改即可，必要时展开“更多设置/补充要求”输入自由文本。

## 选项设计

| 项目 | 默认方式 | 用户可选方式 |
|---|---|---|
| 产品 | 用户明确点选真实产品卡片 | 图片卡片、版本选项、可选搜索 |
| 平台 | 推荐小红书，显示当前选择 | 小红书 / 公众号；其他平台仅在实现后开放 |
| 人群 | 系统根据产品证据推荐 | 推荐候选画像；“自定义”可选 |
| 场景 | 随推荐人群建议 | 与该产品适配的场景选项；“自定义”可选 |
| 营销目标 | 引导到店体验 | 咨询了解 / 到店体验等既有支持项 |
| 任务名称 | 系统自动生成 | 生成后可改名（若已有支持）；不阻塞主流程 |
| 补充说明 | 留空 | 默认折叠的可选文本框 |

这些选项是营销偏好或假设，不能被表示为真实市场统计、产品能力、门店活动或用户行为。默认值可由用户覆盖；不得重新把可选项变成必填表单。

## 产品目录与图片来源

- Coordinator/IMA 提供从指定线上共享库生成的产品目录能力，保留真实来源标识、完整型号/版本、关联事实条目与图片条目及读取时间。
- 目录索引和必要的短期缓存不等于镜像整个知识库。按页/按需读取元数据和所选产品证据；不要批量复制全部原文或读取本地知识库填充生产目录。
- 产品必须有服务端可校验的稳定引用，与库内真实条目及型号绑定。名称只是展示信息，不能依赖浏览器自报名称/图片 URL 作为事实。
- 预览图通过服务端安全访问或代理获取。现有 B5 是任务证据图片；产品目录发生在建任务之前，需要独立定义已登录目录图片访问边界，不能要求先创建任务才能看到卡片。
- 目录图片请求只接受受控产品/图片引用，服务端映射真实 media_id 与型号。不接受任意 URL 或绕过来源校验，不暴露临时签名或 IMA 凭证。
- 无图时使用明确“暂无图片”的中性占位；不能借用近似型号图。无匹配事实或歧义无法解决的条目不得伪装成可一键生成的完整产品。
- 生成时校验当前产品引用和目录版本，重新取得/核对所选产品的有效证据。条目失效、证据读取失败时显示真实问题；不自动换产品或退回本地/假数据。
- 若使用旧目录缓存，要显示更新时间/失效状态，不将历史读取说成实时成功；缓存策略和限额由 Coordinator/Backend 收口。

## 业务工作流调整

1. 服务端校验产品选择，获取当前同型号事实和图片证据。
2. 根据用户所选选项及默认值形成有效简报；空白的人群/场景不是错误，由 Workflow 自动建议并明确假设。
3. 自动选择一个推荐画像和策略以生成初稿；保留候选与推荐理由，供用户事后切换。
4. 自动生成当前平台的内容及图片方案并执行核验。缺失事实不能补写，核验结果/人工动作清楚呈现。
5. 保存当前输入、默认值、来源、推荐选择和产物；刷新重开保持一致。

只有无法安全确定产品版本、缺必要证据或执行失败时暂停，优先提供选项帮助解决。画像/策略的逐步手工确认作为可选精细模式保留，不阻断正常“一键初稿”。
W0 既有“未手动确认画像/策略则禁止生成”规则需增加自动推荐模式；由 Workflow 提业务规则，Backend 实现状态区分与版本校验，不能用伪造 confirmed 绕过。
本需求不批准自动发布，也不自动放宽 pending/rejected 的导出政策。用户改变产品/平台/人群/目标后按依赖规则失效相关产物，防止旧请求覆盖新选择；重复点击不得造成重复生成和重复收费调用。

## 四角色交付

| 角色 / 任务 | 交付 | 接入责任 |
|---|---|---|
| Coordinator + IMA / CP1 | 真实目录、产品/版本与图文条目映射、可用性边界；收口目录和一键生成契约 | 确认当前单型号限制，扩展目录读取；整合三方草案，更新共享类型/计划并发布提交 |
| Workflow / WP1 | 默认简报、画像/策略推荐、自动初稿模式与推荐理由、必要澄清、事后修订 | 调整 W0 确认规则；与 Backend 区分系统推荐和用户确认，不重新实现已有生成模块 |
| Backend / BP1 | 已登录目录/缩略图访问、产品引用校验、自动建任务与连续生成、状态/版本/保存 | 接续 B4/B5；定义建任务前图片权限、一键运行与现有接口兼容，防重复/过时写入 |
| Frontend / FP1 | 图片产品卡片、可选偏好、一键生成、进度/失败/结果及事后调整 | 主入口替换长表单；保留历史任务，更多设置折叠；以正式契约接通真实数据 |

本次需求由本会话代用户记录与传递；实际公共契约仍由唯一 Coordinator 收口，不另设开发角色、不同时修改其他角色的实现。
Frontend 可先调整交互骨架，Workflow 可先修改规则方案，Backend 可先设计受控引用与执行方案；正式路径不能使用静态假产品/假图片冒充已接入目录。
所有角色保留当前成果，在安全检查点调整下一任务；不要求放弃已有 B4/B5/来源兼容等依赖工作。

## 验收

1. 已登录且服务可用时，用户可以不输入任何文本，点选产品，再点“一键生成营销方案”，获得有证据的画像、策略、内容及核验初稿。
2. 用户不需要先手写任务名称、产品、人群、场景或目标；正常路径中途没有画像/策略强制确认弹窗。
3. 卡片图片和完整型号与真实 IMA 记录对应；选择某版本后只使用该版本事实与图片。
4. 当前提供多少可用产品如实展示；缺图、空目录、读取失败和型号歧义有明确状态，不能用近似产品或假资料补位。
5. 选择公众号、换人群或调整目标可通过选项完成，生成结果相应变化；默认值和系统推荐可见且不被记录为手动确认。
6. 选择产品后的新任务自动保存，刷新可重开；双账号隔离、过时请求防护、重复点击保护仍有效。
7. 核验不足仍显示待核验或拒绝；一键生成不能自动发布或绕过已冻结的导出限制。
8. Frontend 负责浏览器走通正常路径，Workflow 验证推荐/生成与模式区分，Backend 验证接口/存储/隔离，Coordinator 验证真实目录和跨模块接通，用户最终验收。
