# 新 Agent 最小阅读路由

## 当前基线与目的

职责基线 `roles-v2-20261018`：Coordinator 兼任 IMA，Workflow 主导营销业务实现，Backend/Frontend 各自实现服务和交互，不设置独立 QA。用户负责最终验收。
本文件提供最小阅读路由；接口未冻结、模块未集成或未验证，不得报告完成。

## 所有人必读

1. `AGENT_CONTEXT.md`：目标、线上事实边界、凭证和用户隔离。
2. 本文件。
3. 自己的 `docs/agents/<role>.md`。
4. `docs/agent-status.md`：全局事实、当前批次与自己的状态行。
5. 首次切换读 `docs/role-transition-v2.md` 和 `docs/communication.md`；日常按通信约定检查共享信箱。
6. 自己的最近交接；接手旧成果时读取对应交接。基线前交接中的旧角色安排属于历史记录，以新任务包为准。

## 按需读取

- 定向读取当前任务相关文件，不扫描整个项目、知识库、历史日志或其他角色全部源码。
- 上游信息不足时，通过信箱索取函数签名、契约章节、最小样例或交接摘要。
- 不读两个本地知识库、压缩包、`__MACOSX/`、`.workbuddy/memory/`，除非用户明确要求且与当前任务相关。
- 不读取或输出 `.env` 凭证值、令牌、私钥。运行时服务端使用凭证，诊断只报告配置状态。
- 测试夹具只用于测试/开发，不能进入正式运行路径或冒充线上结果。

## 任务与交接格式

每次分配包括：任务 ID、可观察结果、主责、协作方、输入/输出、依赖、验收条件。
各角色维护 `docs/handoffs/<role>.md`；Coordinator 同时接收 IMA 历史交接，后续统一写 coordinator 交接。

```text
角色 / 分支 / worktree：
本次任务 ID / 职责基线 / API 契约提交：
已交付：文件、函数/接口、提交号。
已验证：实际命令、环境和结果；未执行项注明未验证。
接入说明：输入输出、最小样例、对应契约章节。
未完成 / 阻塞：缺什么、由谁处理、信箱消息 ID。
下一步：一个可验收动作。
```

模块负责人自测；集成负责人检查真实接通；用户最终验收。共享看板只由 Coordinator 更新。
提交前、阻塞时和下一安全检查点读取信箱消息及回执；交接文件需通过提交/合并交付，信箱消息应附精确分支、提交和路径。
