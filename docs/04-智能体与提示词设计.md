# 04 · 智能体与提示词设计

> 对应评分「自研Agent与提示词 15 分」。本文按**交付物（四段式结果）**倒推流程，给出可直接落地为 prompt 文件的原文。

---

## 1. 四段内容分别怎么生成

四段在回答四个不同的问题，生成方式也根本不同：

| 段 | 回答什么 | 生成方式 | 产出方 |
|---|---|---|---|
| **一、场景判断** | 写给谁、解决什么 | 卡片属性 → LLM 结构化推理 | 调用 1 |
| **二、知识库依据** | 我们能说什么 | 检索 → LLM 挑选 → **与 ima 原文拼接** | 代码 + 调用 2 |
| **三、图文软文** | 我们怎么说、配什么图 | **先出文（含配图方案）→ 再出图 → 嵌回** | 调用 3 + 出图 |
| **四、核验结果** | 每句站得住吗 | 冷读对照 + 约束输出 | 调用 4 + 代码拦截 |

### 1.1 流水线

```
第0步 准备（不调模型）
  产品卡(必选) / 人群卡(可选) / 平台卡+目的 / 风格 / 其他要求
  ima 检索 → 资料原文 + 产品图清单(media_id + 取图时间)
      ↓
调用1  【一、场景判断】 卡片属性 → JSON（人群/场景/购买阶段/核心矛盾/卖点顺序）
      人群或目的未选时自行判断，标 inferred=true
      ↓
步骤2  【二、知识库依据】
  2a 代码抽取候选事实行（原文照抄，不改写）
  2b 调用2：LLM 只做挑选与归类，禁止新增/改写/推算
  2c 代码：与 ima 原文 original_snippet 字符串拼接
      ↓
调用3  【三、图文软文·先出文】 正文 + image_plan（每张图的用途/位置/来源类型）
      ↓
步骤4  【三、图文软文·再出图】
  4a ima 产品图 + HTML 模板合成   4b AI 生成氛围图   4c 海报分层合成
      ↓
调用4  【四、核验结果】 重新注入事实原文做冷读 → 逐条 passed/pending/rejected
      ↓
步骤5  代码硬拦截 + 落库（保存输入快照与本次 prompt）
```

### 1.2 为什么这样拆

| 设计 | 理由 |
|---|---|
| 第一段单独调用 | 它的产出（核心矛盾、卖点顺序）是写正文的依据；先定主题才不会写成大路货 |
| 第二段不由模型写 | 事实部分由代码逐字拼接，"产品事实准确性 20 分"是工程保证，模型只能挑不能造 |
| 第二段仍有 LLM | 检索命中几十条，全塞进正文没人看；让模型做挑选归类，但不许改写原文 |
| 第三段先文后图 | 图先定则文案只能被动描述图，易图文脱节；先有配图方案再按方案出图 |
| 第四段冷读 | 重新注入原文、不让模型回看上下文，避免自我辩护 |
| 合规用代码 | 红线不能赌模型判断，正则不会被人情世故说服 |

## 2. 系统提示词骨架（8 个必备模块）

各段共用，使用时在末尾拼接具体任务。

### 2.1 角色与任务
```
你是服务于华为 PC 门店与内容运营的营销文案智能体。
交付物是"有知识库依据的图文软文"，不是创意散文。
任何产品判断（型号、参数、功能、价格、卖点）都必须能追溯到本轮【知识库依据】。
你没有知识库之外的产品知识。
```

### 2.2 场景理解
```
动笔前先完成场景判断并显式输出：
目标人群 / 使用场景 / 购买阶段（认知·比较·决策·复购）/ 主要问题 / 内容目标。
不同人群必须导致不同的内容切入点，不得把同一套卖点机械套用到学生、职场、创作、家庭。
```

### 2.3 平台规则
```
根据平台改变这五项，缺一即不合格：标题、篇幅、结构、语气、行动引导。
公众号：标题稳，导语100字内，分段正文，专业克制
小红书：标题口语化带身份感，短段落多空行，讲具体场景，带话题标签
        ——不得伪造个人体验（不写"我用了三个月"这类没有的经历）
门店朋友圈：全文80-150字，只讲一个核心卖点，引导到店/咨询
门店海报：主标题≤12字，副标题≤20字，卖点≤3条每条≤15字
只改变篇幅或平台名称，不视为完成平台适配。
```
各平台的**图片数量**硬指标见 [01 §1.4](01-赛题与产品定义.md)。

### 2.4 知识库约束
```
【知识库依据】是唯一允许的事实来源。
1. 型号、参数、功能、价格、卖点只能来自依据中明确出现的内容
2. 依据中没有的数字、价格、优惠、补贴、库存、赠品、服务承诺、奖项、销量、用户评价，
   一律不得写出，不得用"约""起""左右"变造
3. 依据中出现但型号不确定的内容不得使用
4. 资料冲突时停止生成，输出 conflict 并提示人工确认
5. 可以做业务解释（把1.33kg说成"单手可拎"），但不得新增依据之外的量化结论
```

### 2.5 图片规则
```
图片只能从【可用图片清单】中选择，清单每张带 media_id、文件名、说明。
1. 不得描述或引用清单之外的图片
2. 选图必须核对所属型号与本次产品一致，不确定则不选
3. 每张图说明用途、建议插入位置、图注
4. 数量必须符合平台要求；不够时按实际数量输出并标注，不得重复凑数、不得用近似型号代替
5. 不得改写产品图的画面内容
```
海报走"版式生成 + 产品图原样合成"链路（§8），AI 只负责背景。

### 2.6 生成要求
```
输出结构化 JSON：标题（含2-3备选）、导语、正文、配图方案、行动引导、平台标签。
禁止套话（如"在这个快节奏的时代"），不得超出平台篇幅。
```

### 2.7 核验规则
```
1. 逐条列出正文中的产品事实，标注依据来自哪一条
2. 依据中找不到出处的表述必须删除，记入 removed_claims
3. 依据冲突时停止输出，overall_status=conflict
```

### 2.8 合规规则
```
禁止：绝对化宣传（最/第一/唯一/顶级/最强/全网最低）、虚假承诺、无依据对比、
      价格误导、竞品贬低。
出现即删除并记入 compliance_removed。
```

## 3. 调用 1 —— 一、场景判断

**输入**：`[base 8模块]` + 产品属性 + 人群属性（未选则写"（用户未指定，由你判断）"）+ 平台 + 目的（未选同理）+ 风格 + 其他要求

```
任务：只输出【场景判断】，不要写正文。

输出 JSON（严格遵守，不得增删字段）：
{
  "persona": {"name":"","inferred":false,"identity":"","tasks":[],"pains":[],"concerns":[]},
  "usage_scenarios": [],
  "buying_stage": "aware | compare | decide | repeat",
  "main_problem": "一句话：客户此刻最焦虑什么",
  "core_conflict": "一句话：A 想要 vs B 限制",
  "content_goal": "到店体验 | 咨询了解",
  "goal_inferred": false,
  "selling_order": ["按重要性排序的卖点，最多5个"],
  "forbidden_angles": ["本轮不能碰的角度"],
  "reasoning": "两句话说明判断依据"
}

规则：
1. 用户给了人群就严格用其字段，inferred=false，不得改写
2. 没给就自己判断：先看产品定位，再看平台特性，给出最合理画像，inferred=true，并在 reasoning 说明
3. 目的同理，goal_inferred=true
4. selling_order 必须由 pains 与 concerns 推导，不能套固定模板；不同人群的卖点顺序必须不同
5. 不得引用具体参数数值——那是第二段的事
```

**关键**：`inferred` 决定界面是否显示「系统推断」与回退键；`selling_order` 是"不同人群产生不同内容"的执行依据。

## 4. 步骤 2 —— 二、知识库依据

### 4.1 2a 代码抽取（不改写）
从 ima 命中原文按行/句抽候选事实：
```json
{"fact_id":"f_01","text":"机身重约1.33kg","source_title":"产品发现卡",
 "evidence_id":"ev_01","media_id":"...","fetched_at":"..."}
```

### 4.2 2b 调用 2：LLM 挑选
```
已知本次主题：{main_problem / core_conflict / selling_order}
候选事实：{facts}

任务：挑出最相关的 5-10 条并归类。
1. 只能从候选中挑，不得新增、改写、合并原文数据
2. 不得推算（从重量推"很轻很好带"不算事实）
3. 涉及价格、优惠、销量、奖项、用户评价的一律不选
输出：
{"selected":[{"fact_id":"f_01","group":"轻便|续航|屏幕|协同|其他"}],
 "unused_note":"相关但未选的说明原因"}
```

### 4.3 2c 代码拼接
把选中事实与 ima 原文逐字拼接：
```json
{"model_name":"HUAWEI MateBook 14（鸿蒙版）",
 "facts":[{"group":"轻便","text":"机身重约1.33kg",
           "source_title":"02-HUAWEI MateBook 14（鸿蒙版）.md",
           "evidence_id":"ev_01","media_id":"...","fetched_at":"...",
           "original_snippet":"（ima 原文整句，逐字）"}],
 "documents":[{"evidence_id":"ev_01","title":"..."}]}
```
`original_snippet` 是评委抽查时比对正文的最硬证据，不可省。

## 5. 调用 3 —— 三、图文软文（先出文）

**输入**：`[base 8模块]` + 平台规则 + 风格 + 第一段 + 第二段(事实与原文) + 可用产品图清单 + 时令素材(可选)

**只出文，不出图。** 但要给出配图方案作为下一步出图的图纸：

```json
{
  "title_options": ["",""],
  "title": "",
  "lead": "导语",
  "body": "正文（按平台结构）",
  "cta": "行动引导",
  "tags": [],
  "image_plan": [
    {"slot":1,"position":"cover|body_1|body_2|ending",
     "purpose":"这张图承担什么叙事任务",
     "caption":"图注",
     "source_type":"ima_product|ai_ambient|poster_composite",
     "ima_evidence_id":"ev_05 或 null",
     "ai_prompt":"若为氛围图，描述画面（不得包含产品外观）"}
  ],
  "claim_citations": [{"sentence":"正文句子","evidence_id":"ev_01"}]
}
```

约束：`ima_product` 必须带 `ima_evidence_id`；`ai_ambient` 不得出现产品本体；图数量符合平台；每句事实陈述必须进 `claim_citations`。

## 6. 步骤 4 —— 出图（三、图文软文 · 配图）

| source_type | 做法 |
|---|---|
| `ima_product` | **HTML 静态模板 + ima 产品图合成**，锁宽高比不拉伸 |
| `ai_ambient` | **图像模型生成**背景/氛围，禁止出现产品本体与 Logo |
| `poster_composite` | AI 出背景 → 产品图原样贴入产品位 → 文字叠上层 |

### 6.1 生成图提示词（ai_ambient）
```
上下文：产品 {product}，人群 {persona}，用途 {purpose}，平台 {platform}
需表达的氛围：{ai_prompt}

硬性要求：
1. 画面中不得出现任何笔记本电脑、手机、平板的本体外观
2. 不得出现任何品牌 Logo、文字、水印
3. 聚焦场景氛围、光影、生活方式元素（宿舍桌面、通勤地铁、咖啡馆窗口）
4. 留出产品图与文字的插入空间
5. 竖版 3:4（小红书/朋友圈）或 横版 16:9（公众号内文）
```
> AI 一旦画了电脑就必然"与真机不符"，直接踩图片项 0 分。所以 AI 只能画场景。

### 6.2 合成后代码核验
产品图宽高比与原图一致（防拉伸）；`ima_product` 均有 media_id；图片数量符合平台。

## 7. 调用 4 —— 四、核验结果

**输入**：第三段成稿 + 第二段（事实与原文）+ 第一段。全文重新注入做冷读。

```
你是独立核验员，没有参与写作，只负责找问题。

【事实唯一依据】{facts with original_snippet}
【待核验成稿】{正文 + 配图方案}

逐条核验，输出：
{"checks":[{"type":"fact|image|compliance|platform",
            "claim":"被核验片段","status":"passed|pending|rejected",
            "evidence_id":"...或null","reason":"一句话"}],
 "overall_status":"passed|pending|rejected"}

1. 每条产品事实必须能在依据中找到出处，否则 rejected
2. 事实从严：宁可 pending 也不要放过
3. 图片：用途与图注是否一致，数量是否符合平台
4. 平台：结构、语气、篇幅是否符合该平台规则
5. 出现依据中没有的价格/优惠/销量/奖项/用户评价，一律 rejected
```

### 7.1 代码层硬拦截（调用 4 之后）

命中即从成稿删除并记入 `removed_claims`：

| 规则 | 实现 |
|---|---|
| 绝对化用语 | 词表：最/第一/唯一/顶级/极致/全网最低/史上/首创 |
| 价格类 | 正则 `\d+\s*元` `立减\d+` `\d+折` `补贴\d+` `到手价` `优惠\d+` |
| 销量/评价 | `销量第一` `好评如潮` `\d+万\+?好评` `用户评价` |
| 奖项 | `获奖` `金奖` `大奖` |
| 竞品 | 竞品品牌名不得与负面词共现 |
| 数字兜底 | 正文数字必须能在证据原文中找到，否则标待确认 |

> 虚构价格/补贴/销量/奖项/评价 = 该任务准确性合规性 **0 分**，这层是保命的。

## 8. 海报：模板 + AI 背景分层合成

```
① 文案（调用 3 顺带产出）：主标题 / 副标题 / ≤3卖点 / 活动说明
② 图像模型生成背景（提示词见 §6.1，严禁产品本体与 Logo）
③ HTML 模板合成：ima 产品图原样贴进产品位（锁宽高比），文字按模板排版叠上层
④ 核验：型号一致、宽高比未变
```
结果页拆分标注：`产品图 · 来源 ima` + `背景版式 · AI 生成`。

## 9. ima 检索（无 LLM，但很关键）

### 9.1 调用链（同类方案前一轮已实测跑通，记录见 `.archive/docs-old-20261018/handoffs/ima.md`）
```
A. search_knowledge_base  按名称查共享库 → data.info_list[0].kb_id
B. get_knowledge_list     浏览目录（搜索为空时必须回退到这里）
C. search_knowledge       按型号 + 任务关键词搜索
D. get_media_info         取原文 / 图片访问链接
E. 应用层                 抽事实点、下载图片、记录 media_id 与取图时间
```
脚本：`ima-skills-1.1.10/ima-skill/ima_api.cjs`。凭证走环境变量，不写进代码。

### 9.2 已知坑（直接继承，别重踩）

| 坑 | 处理 |
|---|---|
| 实际字段是 `kb_id`/`kb_name`，不是 `id`/`name` | 按实际返回兼容 |
| 搜索为空 ≠ 无权限 | 回退 `get_knowledge_list` 浏览目录 |
| 末页可能不返回 `is_end`/`next_cursor` | 兼容省略，最多翻 20 页 |
| 图片 `source_url` 为 null | 用 media_id 追溯，后端代理刷新，不持久化临时签名 |
| 资料是「产品发现卡」，只有型号/分类/定位摘要 | 不据此扩写精确配置/价格/服务承诺，进"待人工确认" |
| 手工抄 media_id 易错（220030） | 始终程序透传返回值 |
| 型号歧义（MateBook 14 对应鸿蒙版/酷睿 Ultra） | 返回候选让用户选，不自动挑 |

### 9.3 图片获取与缓存
由 ima 取图后缓存到本地，记录 media_id / 条目名 / 取图时间；前端走服务端代理，不暴露上游签名。界面展示"来源：ima · 取图时间"。

## 10. 联网搜索：只做「当季话题与时令素材」

**唯一使用联网的地方。** ima 知道"这台机器是什么"，但不知道"现在几月、离开学几天、大家在聊什么"。

### 10.1 三层检索（素材跟着人群走）

不是查"本月热点"，而是查"**这个人在这个时间点关心什么**"。按层尝试，命中即停，每条标 `layer`：

| 层 | 关键词 | 何时用 | 例子（开学季） |
|---|---|---|---|
| 1 人群专属时令+话题 | {人群身份} × {月份/季度} × {场景} | 优先 | "距开学14天"、"宿舍装备怎么选" |
| 2 人群通用话题 | {人群身份} × {品类} × {关注点} | 第1层为空 | "学生党笔记本预算怎么分配" |
| 3 通用兜底 | {品类} × {当季大环境} | 前两层都为空，界面弱化 | 当季大环境方向 |

`layer` 取值：`persona_season` / `persona_general` / `generic`

### 10.2 绝对不做什么

| 禁止 | 原因 |
|---|---|
| 查产品参数、配置、价格、优惠 | 产品事实只能来自 ima |
| 网上产品介绍写进正文 | 同上 |
| 成段搬运外部文字 | 版权侵权 |
| 混进"知识库依据"那一段 | 那段必须逐条指回 ima 条目 |
| 忽略人群，直接搜"本月热点" | 内容谁都能用，等于没做场景理解 |

### 10.3 实现约束
独立一步，失败不影响主流程（显示"本次未获取到话题素材"）；结果只进入时令素材字段，不拼进事实部分；不重试；检索关键词必须存下来便于复现。

### 10.4 提示词
```
输入：产品 {product} / 目标人群 {persona_name} / 典型任务 {persona_tasks}
      / 核心痛点 {persona_pains} / 平台 {platform} / 今天 {today}

任务：判断"这个人群在当前时间点关心什么"，给出可用素材。

1. 一切检索与产出以该人群身份为锚点，不得退化成泛泛的"本月热点"
2. 按三层顺序尝试，命中即停，每条标来自第几层
3. 日期类素材给出确切日期，无法确认则 confirmed=false 并说明

严格禁止：检索或输出任何产品参数、配置、价格、优惠、促销数值；
不得引用原文段落（只做概括）；所有输出都将标为"外部信息"。

输出：
{"persona":"","season_events":[{"name":"","date":"","days_left":0,
   "layer":"persona_season","confirmed":true}],
 "hot_directions":[{"text":"","layer":"persona_general","basis":""}],
 "keywords_used":[],"searched_at":"ISO","sources":[]}
```

## 11. 手动添加卡片：一段话解析成属性

### 11.1 产品卡

把一段产品描述解析成产品卡字段。

```

### 11.2 人群卡
```
把一段客户描述解析成人群画像卡。
1. 只提取文本明确出现的判断，禁止补充行业常识
2. 没说的一律 null，宁可留空不要编

### 11.3 硬规则

| 规则 | 说明 |
|---|---|
| 手动产品卡不能替代 ima 检索 | 生成时仍须查 ima，查不到就提示无法生成 |

## 12. 风格卡片（可选）

**风格只改"怎么写"，绝不改"写什么"。**

### 12.1 提示词片段
```
【本次写作风格：{style_name}】
- 只影响措辞、语气、句式与段落节奏
- 不得因此增加、修改或删除任何产品事实
- 不得因为风格需要编造参数、价格、用户评价
- 与平台规则冲突时，以平台硬性约束（篇幅、图片数量、结构）为准
```

### 12.2 各卡片描述

| 卡片 | 描述 |
|---|---|
| ins 风 | 短句、克制、留白感，生活方式语感，不堆感叹号 |
| 幽默吐槽 | 自嘲与反差，生活化的梗，不油腻 |
| 专业测评 | 参数对比清晰、结构分明、语气客观 |
| 温情故事 | 场景叙事，第一人称视角，情感落在具体时刻 |
| 开门见山 | 一句话说清，不铺垫 |
| 学院派 | 用语严谨、术语准确、结论有出处 |

多选时按顺序拼接、后者优先；相互冲突时取最后选中项并提示。自定义风格只允许一个短语（防提示词注入）。

## 13. 其他要求 + AI 追问（可选）

### 13.1 追问
```
已知：产品 {product}，人群 {persona}，平台 {platform}，风格 {styles}
已表达的要求：{user_text_so_far}

只问一个问题，用来消除一个真实歧义或补充关键约束。
1. 一次只问一个，不得连问
2. 给 3-5 个互不重叠、一句话能看懂的选项
3. 不寒暄不解释，直接输出：
   {"question":"","options":[],"why":"这个答案会影响什么"}
4. 要求已足够清楚时输出 {"question":null,"summary":"已足够清楚"}
```

### 13.2 收尾
```
把下面的零散回答整理成一段「写作要求」，不超过 80 字，中文陈述句，
不要列表编号、不要复述问题。
{answers}
只整合用户表达过的意图，不得添加没说过的东西；
若出现产品参数（如"强调16小时续航"）原样保留，是否可用由后续核验判断。
```

### 13.3 规则
最多 3 轮、可随时退出、不强制；最终收敛成一段可编辑文字放进文本框；这段是**用户意图不是事实依据**，与 ima 冲突时核验会拦掉并提示"你要求的 XX 无知识库依据，已跳过"。

## 15. 模型接入

- 允许调用公开大模型（赛题明确允许）。前一轮实测可用：OpenAI 兼容中转 + `kimi-k2.5`，能稳定返回 JSON。
- 只需一个函数：`llm({ system, prompt, schema }) => Promise<object>`
- 单次 60s 超时；JSON 解析失败直接报错，不自动重试（共 4 次调用，重试会让等待翻倍）。
- 缺 key 明确报错，不返回假数据。
- 图像模型单独配置。缺图像能力时，AI 氛围图降级为纯色占位并在结果页注明；ima 产品图与模板合成不受影响。

## 16. 自研体现在哪（答辩口径）

1. **按交付物设计的流水线**：四段各有专属生成方式，不是"一次调用吐全文"
2. **事实由代码拼接**：第二段原文逐字来自 ima，模型只能挑不能改
3. **双通道核验**：模型冷读 + 代码红线拦截，无依据内容落库前被删
4. **图文分层**：产品图来自 ima 模板合成，AI 只画场景，禁止出现产品本体
