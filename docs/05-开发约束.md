# 05 · 开发约束（防过度开发）

> 这份文档**不是技术设计稿**，是给执行者（人或智能体）立的规矩。
> 上一轮失败的直接原因：没人约束"该做多少"，于是花了大把时间在工程规范、抽象封装、测试框架上，真正的功能没跑通。
>
> **项目性质：一次性的展示演示。** 判断标准只有一条——**演示现场能不能点通、能不能讲清**。

---

## 1. 铁律（违反即返工）

### 1.1 先规划，再写代码

任何一批工作开始前，先交一份**不超过 20 行**的计划：

```
本批目标：一句话
改动范围：哪些文件/页面
预计耗时：X 小时（时间盒）
验收方式：我点哪里、看到什么，就算完成
不做的事：明确列出本批不碰的东西
```

计划未经确认不得动手。**计划里没写的东西，一律不做。**

### 1.2 不实现未经要求的功能

文档里没写的功能、按钮、页面、设置项，**不做**。
不确定要不要做 → 停下来问，不要"顺手加上"。

### 1.3 禁止擅自添加依赖与基础设施

明确禁止：

- Docker / docker-compose
- CI/CD（GitHub Actions、Jenkins 等）
- 复杂测试框架（Jest/Vitest/Pytest + 覆盖率 + mock 体系）
- ORM / 迁移工具（Prisma、TypeORM、Alembic 等）
- 状态管理库（Redux、Zustand、MobX）
- UI 组件库全家桶（只允许一个现成模板或手写 CSS）
- 微服务拆分、消息队列、缓存中间件、nginx
- GraphQL、tRPC、OpenAPI 代码生成
- 任何"为了以后好扩展"的抽象层

**新增任何依赖前必须先说明理由并获准**。能用标准库解决的一律用标准库。

### 1.4 达到最低要求即停止

功能**能演示**就停手，不要继续做：

- 不要继续重构、拆文件、改名
- 不要补边界情况、不要补错误码枚举
- 不要写单元测试（除了"能证明主链路跑通"的那一次手动验证）
- 不要优化性能、不要做响应式适配（除非演示要投屏到特定尺寸）
- 不要写注释文档、不要补 JSDoc

> 判据：**如果这段代码删掉，演示效果不变 → 就不该写。**

### 1.5 复杂度预算（超预算必须报告，不得硬扛）

| 对象 | 预算 |
|---|---|
| 单个文件 | ≤ 400 行 |
| 单次生成链路 | ≤ 4 次 LLM 调用（场景判断 / 事实挑选 / 写文 / 核验）+ 出图调用 |
| 数据库表 | ≤ 5 张 |
| 项目目录深度 | ≤ 3 层 |
| 单批开发时间盒 | 4 小时 |
| 单次响应耗时 | ≤ 60 秒（超过就拆步骤、给进度） |

**任何一项超预算，先停下来说明"为什么必须超"，不得默默继续。**

### 1.6 时间盒到点即砍，不延期

时间盒用完而功能没完成 → **砍范围**（把功能降级到最小可用），而不是延长工时。
例如"编辑功能"做不完，就只支持改标题和正文，换图留空。

## 2. 唯一的架构要求：一个仓库、一个进程

```
tuijian/
├── package.json          # 一个依赖清单，一个 npm run dev
├── .env.example          # 只有变量名
├── prompts/              # 提示词文本
├── data/                 # 数据库文件 + 图片缓存（gitignore）
└── src/
    ├── server.js         # 后端路由 + 静态托管
    ├── ima.js            # ima 检索
    ├── llm.js            # 模型调用
    ├── pipeline.js       # 生成编排
    ├── verify.js         # 代码级核验拦截
    ├── db.js             # SQLite 读写
    └── web/              # 前端页面
```

就这么平。**不要分包、不要 workspace、不要分层架构、不要 src/domain/application/infrastructure 那套。**

技术选择建议（不是命令）：
- 前后端同语言（Node），省掉一层对接成本
- 存储用 SQLite 单文件（`node:sqlite` 内置），零安装
- 进度用轮询即可，不必上 WebSocket

## 3. 不能打折的部分

工程细节可以随便，但这几条必须按 [01](01-赛题与产品定义.md) 与 [04](04-智能体与提示词设计.md) 做死：

- **四段式输出**（赛题指定格式）
- **第二段原文逐字来自 ima**，保留 `original_snippet` 供评委比对
- **每张图片记 media_id 与取图时间**（否则图片项 0 分）
- **代码级拦截**价格/绝对化/销量/奖项（否则准确性合规性 0 分）
- **四段生成过程可见** + 底部折叠展示真实 prompt
- **四平台图数与结构不同**
- **联网素材单独成栏标「外部信息」**，手动加的卡必须回查 ima，风格只改写法不改事实
- **`prompts/` 里 8 个模块真实存在**，凭证不进代码与日志

## 4. 开发顺序（按页面切，不按模块切）

**开发模式：纵向切片 + 时间盒 + 稻草人先行。**

- 每一批都切穿前后端，交付**一个能在浏览器里点完的完整动作**
- 每批固定时间盒，到点没做完就**砍范围**，不延期
- 先做最丑但端到端能跑的版本（稻草人），再回头美化

| 批次 | 交付 | 完成判据（能看到什么） | 时间盒 |
|---|---|---|---|
| **M0 稻草人** | 一个按钮调一次真实生成，结果裸着打印在页面上 | 证明 ima 通、模型返 JSON、前后端对上 | 2h |
| **M1 骨架** | 8 个页面能互相跳转，登录页能进 | 浏览器点一遍不报错 | 2h |
| **M2 主链路** | P1 选择 → P2 分段进度 → 四段结果（接真 ima + 真 LLM，先做 a/b 两段） | 选产品真实生成出一次四段结果 | 6h |
| **M2.5 出图** | 第三段配图：ima 产品图模板合成 + AI 氛围图 | 结果页能看到合成后的图 | 3h |
| **M3 平台差异** | 四个平台都能出结果，图数/结构/语气不同 | 同一产品四平台各生成一次 | 3h |
| **M3.5 时令素材** | 联网产出"当季话题与时令素材"栏，可选用 | 生成结果里能看到时间节点与讨论方向 | 2h |
| **M4 编辑与导出** | 结果可编辑、复制、下载、底部折叠展示 prompt | 改标题后保存，核验重跑；能展开看 prompt | 2h |
| **M4.5 手动加卡** | 产品与人群都能"粘一段话 → 解析成卡片字段" | 两类卡各粘一段话都能建卡 | 2h |
| **M4.6 可选模块** | 风格小卡片 + 其他要求（含 AI 追问） | 不选也能生成；选了风格写法变、事实不变 | 2h |
| **M5 客户（次要）** | 粘贴解析 → 客户池 → 详情 → 留资页 | 粘一段聊天记录看到客户卡 | 4h |
| **M6 培训（次要）** | 话术生成 + 自测对话 | 选产品+画像出话术，能聊一轮 | 3h |
| **M7 打磨** | 空/错/加载状态、历史记录 | 断网、无结果各跑一次 | 2h |

**M2 没跑通之前，不许碰 M5、M6。** 前 5 批覆盖约 85 分，M5/M6 是加厚。

每一批结束都要有一次**真实的浏览器验证**（不是"单元测试通过"）。

## 5. 数据（够用就行）

只需要 4 张表，字段做到"页面能显示"为止：

| 表 | 存什么 |
|---|---|
| `tasks` | 一次生成：产品、人群、平台、状态、四段结果 JSON、时间 |
| `evidences` | 本次用到的资料与图片：media_id、标题、摘录、本地缓存路径、取图时间 |
| `leads` | 客户卡：姓名、电话、来源、意向产品、阶段、意愿分、下一步 |
| `lead_notes` | 沟通记录：原文、AI 摘要、时间 |

判据：**页面用到什么字段就存什么，不预埋没用的列。**

---

## 6. 安全底线

- 凭证只从环境变量读，`.env` 进 gitignore
- 任何接口不返回凭证，界面不显示凭证片段
- 图片经服务端代理，不把上游临时链接直接交给前端
- 交付前自查一次：仓库里搜不到 key

---

## 7. 遇到问题怎么办

| 情况 | 做法 |
|---|---|
| 需求没写清楚 | 停下来问，不要自己补设定 |
| 某个接口跑不通 | 明确报告"这一步卡住"，**不要用假数据绕过** |
| 预算快超了 | 报告中止，给两个选项（砍范围 / 说明为什么必须超） |
| 发现自己想做"顺手的小优化" | 不做。记在最后的"可做但没做"清单里 |
| 不确定某个功能是否算越界 | 默认不做 |
