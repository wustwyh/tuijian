# MVP Demo 方案 — 华为 PC 营销智能体

## 1. Demo 目标

用最小功能证明：系统能围绕一个华为 PC 产品，为不同人群和平台生成有依据、可核验、可导出的营销内容，并能沉淀单个客户的需求和跟进动作。

## 2. 首版用户旅程

1. 营销员登录。
2. 从真实产品图片卡片选择明确型号；默认采用系统推荐方案，可选平台、人群、场景和目标，无必填文本。
3. 点击“一键生成营销方案”，系统自动建任务并读取线上 ima 同型号事实和图片。
4. 系统推荐客群画像，并保留候选与理由供事后修改，不要求正常路径逐步确认。
5. 系统自动生成推荐策略。
6. 系统连续生成当前平台内容与配图方案；用户可在结果页通过选项调整后重生成。
7. 系统逐项核验事实、图片、平台和合规风险。
8. 营销员导出成稿，并把当前客户加入跟进列表。
9. 营销员记录一次跟进结果和下一步动作。

## 3. 页面控制为 4 个

### 3.1 登录页

- 登录、注册、退出。
- 未登录访问其他页面时跳回登录。

### 3.2 任务列表页

- 当前用户的任务列表。
- 主入口为“选产品生成方案”：真实图片卡片＋型号/版本选项；原任务列表保留为历史记录。
- 按状态筛选：草稿、已检索、已生成、待核验、已完成。

### 3.3 任务工作台

一个任务页完成主要演示，分成 5 个标签页：

1. **任务**：所选产品、平台与系统推荐人群/场景/目标；可选调整，补充文本默认折叠。
2. **画像**：2—3 个候选人群及痛点/顾虑/切入点。
3. **策略**：主矛盾、卖点、内容角度、CTA。
4. **内容**：标题、正文/卡片、图片方案、海报文案。
5. **核验**：事实、图片、平台、合规、导出。

### 3.4 客户跟进页

- 客户姓名/称呼、来源、需求、意向阶段、下一步时间。
- 跟进记录列表。
- 可从任务结果一键生成“下一步建议”。

## 4. 首版业务流程

### 4.1 产品客群画像

输入：产品证据包、目标平台、营销员提供的人群提示。

输出：每个人群包含：

- 人群名称
- 典型任务
- 痛点
- 购买触发点
- 主要顾虑
- 内容切入点
- 适合强调的产品事实
- 待人工确认项

边界：这不是全网市场调研报告，不宣称拥有真实市场份额或用户统计；没有来源时写“基于产品事实的营销假设”。

### 4.2 单个客户需求与跟踪

首版只做轻量 CRM：

- 客户基础信息
- 需求标签
- 预算/时间/使用场景
- 意向阶段：初识、有兴趣、对比中、待跟进、已成交、流失
- 跟进记录与下一步动作

边界：Demo 使用虚构客户；不导入真实手机号、微信号等敏感信息。

### 4.3 产品运行策略

这里理解为“营销运行策略”，不是产品技术运维。输出：

- 本次只解决的一个主矛盾
- 主要人群与次要人群
- 核心卖点和证据
- 平台内容结构
- 行动引导
- 不能说的内容与风险

### 4.4 平台 AIGC 广告/海报

候选平台范围如下；首版最低交付两个平台，当前工作包先实现公众号和小红书。其余平台及可下载海报/卡片成品的具体格式由用户收口，不能把下列列表当作四平台全部已分配或实现：

- 公众号图文
- 小红书图文
- 朋友圈短文
- 门店海报文案与版式说明

图片规则：

- 只使用线上 ima 返回的产品图或官方素材。
- 海报可以生成 HTML/SVG 版式，把 ima 图片嵌入为产品图。
- 不用 AI 重新生成产品外观，不修改图中参数和脚注。

## 5. Demo 用例

### 用例 A：换人群

- 产品：HUAWEI MateBook 14（鸿蒙版）
- 平台：小红书
- 人群：准备开学的大学生
- 场景：课堂笔记、社团资料、宿舍学习
- 预期：输出 3—6 张图的小红书图文；重点围绕便携、屏幕、协同和预算边界。

### 用例 B：换平台

- 产品：HUAWEI MateBook 14（鸿蒙版）
- 平台：微信公众号
- 人群：经常移动办公的职场人
- 场景：差旅、会议、跨设备协同
- 预期：输出 2—4 张图的公众号文章；结构更完整，强调场景问题、证据和核验动作。

### 用例 C：歧义处理

- 输入：“给 MateBook 14 做一张门店海报”
- 预期：系统识别可能有鸿蒙版/其他配置，先要求选择具体版本；不得自行套用相近型号事实。

## 6. 比赛评分映射

| 评分点 | Demo 展示方式 |
|---|---|
| 业务场景理解 | 用例 A/B 对比不同人群与平台 |
| 产品事实准确性 | 核验页展示线上 ima 证据和待核验项 |
| 图文生成与图片引用 | 内容页逐图显示 media_id、用途、图注 |
| 平台适配与软文质量 | 小红书卡片与公众号长文对比 |
| 自研 Agent 与提示词 | 展示画像 → 策略 → 生成 → 核验流程 |
| 功能完成度与体验 | 登录、任务保存、编辑、导出、客户跟进 |
| 合规与安全 | 风险清单、人工确认项、无来源不生成 |

## 7. 演示脚本

1. 登录营销员账号。
2. 选择线上目录的 MateBook 14 明确版本卡片；可选大学生/小红书，直接一键生成，系统自动命名任务。
3. 展示线上 ima 检索记录和产品图片。
4. 展示系统推荐画像及理由；正常路径无需逐阶段人工确认，可在结果页修改。
5. 生成小红书图文和配图方案。
6. 通过选项将同产品切换为公众号/移动办公人群并生成；无需重新填写整张任务表。
7. 展示策略和文风变化。
8. 打开核验页，说明哪些事实通过、哪些需要人工确认。
9. 导出一组结果。
10. 添加一个虚构客户，生成下一步跟进建议。

## 8. 首版验收清单

新增 PR1 验收：已登录用户无需输入文本，选定产品后一次触发生成完整初稿；正常路径没有画像/策略强制确认。详见 `requirements/product-selection-one-click.md`，它替代旧的长表单入口要求。

- [ ] 未登录不能进入任务页。
- [ ] 用户只能看到自己的任务和客户。
- [ ] 创建任务后能从线上 ima 查到产品资料。
- [ ] 至少能读取 1 份 Markdown 资料和 1 张产品图片。
- [ ] 画像、策略、内容都能保存并重新打开。
- [ ] 同一产品换人群后，内容切入点明显不同。
- [ ] 同一产品换平台后，结构、语气、图片数量和 CTA 明显不同。
- [ ] 型号歧义能被追问，不自动混用。
- [ ] 所有事实有来源；未知项显示“待人工核验”。
- [ ] 导出结果包含成稿、图片方案和核验清单。


## 9. 实施责任与验收方式（职责基线 v2）

- Coordinator（兼 IMA）负责线上知识接入、公共契约与工程集成，维护演示步骤。
- Workflow 主导任务理解、画像、策略、平台内容、核验、反馈修订与下一步跟进建议的业务逻辑。
- Backend 负责身份、持久化、LLM 适配器、图片访问、执行状态与导出。
- Frontend 负责操作、确认/修订、内容预览、证据与核验展示。Workflow 交付配图语义，Frontend 实现约定的排版预览；可下载成品格式确认后再落实对应导出。
- 不设置独立 QA。模块负责人自验，Coordinator 检查最小真实闭环，用户最终评估体验与营销效果。详细责任见 `demo/acceptance.md`。

原 A/B 演示同时改变人群和平台；补充两组单变量对照：固定平台只换人群、固定人群只换平台。用例 C 首先验收型号歧义处理，不能据此宣称海报成品已经实现。
本次职责调整不擅自取消客户跟进、不扩展到全量四平台或图像成品。未明确的产品范围由用户决定。
