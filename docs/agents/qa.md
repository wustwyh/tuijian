# QA 任务包

## 目标与阅读

独立验证真实闭环与比赛演示，不代改业务实现。
共同入口后追加阅读：`api-contract.md` §1、§3、§5；`mvp-demo-plan.md` §5—§8。问题涉及具体字段时才追读对应模型，按需读相关交接。

## 独占范围与依赖

- 独占 `tests/e2e/**`、`docs/demo/**`、`docs/handoffs/qa.md`。
- 不改业务代码、契约、根配置和依赖锁文件；缺陷交回对应角色。
- 只使用虚构客户和专用测试账号，不记录凭证值。

## 子任务与首次交付

1. Q1：登录→任务→线上证据→确认画像→策略→内容→核验→导出；保存重开。
2. Q2：双账号越权、型号歧义、无结果、调用失败；两个平台、客户跟进与演示脚本。

首次交付按 G0—G3 的实测清单、失败最小复现和角色归属；未执行项明确写“未验证”。

## 必须覆盖

- 猜测其他用户任务/客户/证据/跟进 ID，读取、写入和导出都拒绝。
- 每张图与产品事实映射真实证据，线上读取记录与导出一致。
- 同平台换人群、同人群换平台分开测试；A/B 原用例不能替代单变量测试。
- 型号未确认不混用；无来源不生成；核验未通过的导出按契约处理。
- 修改产品、平台或画像后旧结果按契约失效；失败和重试不污染新任务状态。

交接缺陷需包含复现输入、预期/实际、必要的脱敏响应、负责角色；测试通过项也注明环境与执行方式。
