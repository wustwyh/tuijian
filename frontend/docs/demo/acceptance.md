# 模块自验、集成检查与用户验收

职责基线 `roles-v2-20261018` 暂不设置独立 QA。原 Q1/Q2 的必要覆盖保留如下；产品运行时内容核验仍由 Workflow 实现。
此处是待检查清单，不表示任何项已执行。结果记录环境、版本、命令/操作、预期/实际、证据与未验证项。

| 检查 | 主责 | 协作 / 交付证据 |
|---|---|---|
| IMA 线上 Markdown、图片、来源与适用型号；空结果/鉴权/读取失败 | Coordinator | 脱敏真实响应、调用入口、错误说明 |
| 注册/登录/退出、刷新和持久化重开 | Backend | Frontend 浏览器联调；重启后结果与会话行为 |
| 双账号隔离：猜测任务/客户/证据/跟进 ID，读/写/导出均拒绝 | Backend | Frontend 检查私有界面退出和切换；可复现双账号测试 |
| 任务理解、型号歧义和画像确认前置 | Workflow | Coordinator 提供候选；Backend 保存，Frontend 交互 |
| 同平台换人群、同人群换平台，分别做单变量比较 | Workflow | Frontend 展示真实结果，用户评估营销质量 |
| 无来源数字/价格/评价、错误引用、型号/图片混用、缺图 | Workflow | 确定性规则和真实模型结果分开记录；不足不凑图 |
| 实际图片可访问、有效期和证据映射 | Coordinator + Backend | Frontend 实际显示；元数据不能代替像素/视觉检查 |
| 产品/平台/画像/证据变化后的失效，旧请求不覆盖新输入 | Backend | Workflow 定义依赖，Frontend 展示失效；实际竞态检查 |
| 失败/重试与用户反馈修订，保持证据和版本一致 | Workflow + Backend | Frontend 交互；有限重试不污染新结果 |
| pending/rejected 导出按冻结规则处理 | Backend | Workflow 给核验原因，Frontend 显示限制；不从客户端绕过 |
| 导出内容、图片引用、核验与线上读取记录一致 | Backend | Coordinator 最小闭环检查，Frontend 复制/下载 |
| 虚构客户保存、跟进建议与记录 | Backend + Workflow | Frontend 操作；不发送消息给真实客户 |
| 构建、布局、加载/空/错误/失效状态与操作路径 | Frontend | 构建结果与真实浏览器检查 |
| 登录到导出的最小真实闭环及演示材料 | Coordinator | 模块负责人修复，向用户提交入口、步骤和限制 |
| 最终营销效果、体验与比赛演示 | 用户 | Coordinator 提供已知限制与可复现演示 |

G0—G3 定义见 `../parallel-work-tree.md`。原 A/B 同时改变人群和平台，不替代两组单变量验证。
测试夹具/假 LLM 只证明模块行为；真实 IMA、真实 LLM、真实持久化和完整闭环须分别验证。没有真实依赖时保持未通过，不自动切换假数据。

缺陷格式：复现输入与操作、预期/实际、必要脱敏响应、环境/提交、所属角色、信箱消息 ID。模块负责人修复后复验受影响路径。
