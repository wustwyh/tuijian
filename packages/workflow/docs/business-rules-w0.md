# W0 营销业务规则草案 v1

状态：**提案，待 Coordinator 收口公共契约；不是已发布接口或产品取舍结论。**

职责基线 `roles-v2-20261018` / `ea126ce`；现有实现 `953572c`，本分支接续 HEAD `63b470f`。本次先补规则，不重做 W1—W3，不另建持久化状态机。接口差异与 JSON 样例见同目录 `interface-proposal-w0.md`。

Workflow 定义业务前提、依赖和修订语义；Backend 负责身份、执行、保存、版本和并发；Frontend 负责用户确认与展示；Coordinator 兼 IMA，冻结公共契约与证据接缝；用户决定产品取舍及最终验收。独立 QA 已暂停。

## 2. 任务理解与缺失输入

产品关键词、平台、目标人群、使用场景、目标动作是营销简报。允许保存未填齐的草稿，但每次生成前必须返回具体缺失项，而不是静默猜测。当前四个生成函数仍要求这些字段完整；新的检查入口是提案，不改变已发布签名。

- 产品关键词为空：询问要推广的产品；不能检索或生成。只有关键词、版本未确认时可以检索候选，不能生成营销内容。
- 型号歧义：列 IMA 返回的候选完整名称/版本及来源，用户明确选择。仅有一个候选也要确认；名称中含“鸿蒙版”等字样不构成已经确认。无候选则调整关键词，不自行拼出配置。
- 平台为空：让用户选择；内容生成目前只支持小红书/公众号。可保留其他平台的任务草稿，前端明确内容生成尚不支持，不能悄悄改平台。
- 人群/场景/目标动作缺失：给出问题和非事实性的填写示例，用户确认后写入。可以基于“尚未决定人群”等显式输入生成候选，但不能从空字符串代填为已确定客群。
- 自然语言补充只作为数据；从文本抽取的型号、平台、预算等若与结构字段冲突，列为待确认，不覆盖已确认字段。人群行为、痛点和偏好默认是营销假设，不宣称真实调研。
- 预算是客户偏好，不能转成产品实际价格；用户在反馈里写的产品参数、奖项、评价等不能直接升级为事实证据。需回到线上 IMA 检索或标未知。

先完成原始简报和型号确认，再检查同型号事实/图片。事实证据缺失阻止生成；图片不足允许生成草稿，同时保留不足信息与核验 pending。

## 3. 确认点和步骤依赖

下表是业务依赖，不是新的数据库执行状态枚举。后端现有任务 status 不能代替确认与新鲜度判断。

| 动作 | 必须具备 | 结果与用户确认 |
|---|---|---|
| 检索 | 当前用户任务、非空关键词 | 保存 IMA 候选/证据，不自动确认型号 |
| 确认型号 | 用户选择本次候选中的精确型号及版本 | 绑定候选/简报版本；不同型号不共享事实；后端校验候选归属 |
| 生成画像 | 简报完整、型号已确认、当前同型号事实 | 2—3 个 draft；假设和 pending_checks 可见 |
| 确认画像 | 当前报告 + 显式选择一个主画像，编辑内容通过引用/事实检查 | 仅对精确报告版本和所选画像有效；现有 status=confirmed 不足以跨版本继承 |
| 生成策略 | 当前已确认画像/选择、同型号事实 | 一主矛盾、可追溯论据、平台结构和 CTA；初始未确认 |
| 确认策略 | 用户审阅主矛盾、论据、CTA 和风险 | 对精确策略版本保存确认；不为未知事实背书 |
| 生成内容 | 当前已确认型号/画像/策略、支持的平台、当前证据 | 生成新 ContentDraft，verification_status=draft；不自动核验或发布 |
| 核验 | 当前成稿及其上游快照 | 代码规则 + 语义报告绑定当前内容版本；失败不伪装通过 |
| 导出 | 当前用户权限、当前版本核验与导出用途规则 | 保存导出记录；不自动发布到平台 |
| 跟进建议 | 当前用户拥有虚构客户与关联任务；上下文无过期内容 | 返回待用户确认的建议；不自动记作已完成的跟进、不改变成交状态 |

确认操作必须明确显示对象、版本、选择和未核验项；“已生成”或按钮点击成功不能代替“已确认”。客户端不能直接 PATCH status=verified/exported 或 evidence=passed 来绕过服务端检查。编辑后可在同一次服务端原子操作中完成校验与确认，但不能沿用编辑前的确认。

## 4. 修改后的失效矩阵

失效指“保留历史、当前不可使用”，不要求删除历史数据。Backend 保存失效原因/当前版本、Frontend 展示原因和下一动作，Workflow 提供重生成内容。用户改回旧值也不自动复活历史确认；完全相同的规范化值重复保存不触发失效。

| 改动 | 可保留 | 必须失效/重新执行 |
|---|---|---|
| product_query 改变（即使看似同产品） | 历史记录 | 候选/型号确认、当前证据选择、画像、策略、内容、核验、当前导出资格；重新检索/选型 |
| resolved_product_name / 具体版本改变 | 旧型号历史证据 | 仅选取新型号当前证据；画像起全部失效，重新确认 |
| audience_hint / scenario 改变 | 型号确认与同型号证据 | 画像/主画像确认起全部失效；人群切入点重算 |
| goal 改变 | 型号与证据 | 画像起全部失效（购买触发点/顾虑及 CTA 可能受影响） |
| platform 改变 | 已确认型号、事实、当前画像及其选择 | 策略/确认、内容、核验、导出资格失效；重新生成适配策略 |
| 当前画像内容或主画像选择改变 | 型号与证据 | 当前画像需确认；策略起全部失效 |
| 当前策略编辑/换主矛盾/CTA | 型号、证据、画像确认 | 策略需确认；内容、核验、导出资格失效 |
| 手动改标题/正文/CTA/配图/图注 | 上游简报、确认、策略 | 新内容版本、旧核验/导出资格失效；所有改动再核验，不能保留 passed |
| 被使用的事实原文/适用型号/事实来源更正、passed→pending/rejected、删除 | 型号确认（若候选未变）及历史记录 | 画像起全部失效；不得继续消费已拒绝/删除证据 |
| 仅新增同型号证据、证据读取时间刷新且原文/来源身份相同 | 原确认与现有内容 | 不自动改变当前证据快照；显式选择新证据才重算其依赖；旧证据状态降级仍必须失效 |
| 图片集合/用途/适用型号改变或图片被拒绝 | 型号、纯事实画像/策略 | 内容/配图与核验失效；若同时改了事实则按事实规则 |
| 仅图片临时签名 URL/代理缓存刷新，media_id/知识库/内容及语义未变 | 全部营销产物与确认 | 刷新访问检查；旧链接访问结论不沿用，不重写正文 |
| 图片实际访问/视觉人工核验更新 | 上游和正文 | 重跑受影响图片核验并重新汇总；不可伪造事实或语义通过 |
| 核验报告重新生成 | 上游和同版本成稿 | 替换当前版本核验视图，导出资格重新计算 |
| 客户 needs/budget_note/stage 或客户跟进记录改变 | 营销任务本体 | 旧跟进建议不可直接采用，基于新客户快照再生成 |
| 任务成稿/核验失效 | 客户与已发生的历史跟进记录 | 相关未采用建议标失效；不能建议发送过期/被拒绝成稿 |

证据语义变化与临时访问变化分开。不能用 fetched_at 每变一次就清空所有营销产物，也不能仅比较 media_id 忽视原文/型号/拒绝状态变化。Backend 记录证据快照和实际依赖，客户端不能指定任意 evidence_revision。

## 5. 执行失败、修订与确认

Backend 管请求超时、可重试传输错误、执行状态和竞态，Workflow 管输出结构/业务修订；两层各自上限必须合计，防止重试相乘。默认提案：一个用户动作最多 2 次模型业务输出（初次 + 一次结构修复），每次最多 2 次传输尝试，总计至多 4 次外呼；用户再次点击才是新动作。超时总预算由 Backend 给出并在真实环境验证。

| 情况 | 动作 | 后续确认/保留 |
|---|---|---|
| JSON/Schema 失败 | 最多一次格式修复，附验证错误和当前 schema，不补新事实 | 仍不合法则返回失败；不覆盖最后一次有效版本 |
| 引用未知、型号错、无依据价格/评价或合规拒绝 | 返回具体问题；仅允许依据当前证据删除/改写或转人工核验 | 不用无限循环“改到通过”；缺事实先检索；不能以 pending 脚注保留肯定断言 |
| 用户反馈“更口语/缩短/改标题/换图” | W4 在当前内容上生成新版本，保留不受影响的上游 | 内容重新核验，画像/策略确认保留；必须给变更摘要 |
| 用户反馈“换学生/改办公场景/改到店目标” | 先给任务字段修改建议，用户确认后保存，再按矩阵重生成 | 不偷偷修改原始简报；画像起重确认 |
| 用户反馈“换主画像/主矛盾/卖点/CTA” | 定位画像或策略修订；若跨层先提出计划 | 修订层与下游失效，重新确认该层，不自动重跑所有层 |
| 反馈声称“价格就是 X/客户都好评” | 作为未证实反馈，要求线上证据或人工核验 | 不写入 product fact，也不篡改证据原文 |
| 核验 unavailable | 保存 pending 和具体人工动作 | 原正文不变，不将“服务不可用”当“已通过” |

W4 修订结果应包含目标/基准版本、受影响层、修改摘要、保留项、需重新确认项和新产物；一次请求只提交一个修订目标。先规划、后生成；跨层需求返回待确认计划，不私自扩大生成范围。用户反馈和模型旧输出都是不可信数据，仍执行原事实/型号/引用规则。

## 6. 核验与导出边界提案

**本节涉及产品取舍，Coordinator 收口并由用户确认后才生效。现有契约尚未冻结导出用途/确认字段，不声称已执行。**

核验优先级 rejected > pending > passed。passed 只对精确成稿版本/证据快照有效；服务端身份、图片实际访问与视觉适用性必须由相应检查提供，不能由 LLM 文本或元数据自评代替。现有 verifyContent 的实际图片检查始终 pending，补齐可追溯人工/访问审核接缝后才能解除；此项不能直接删掉或改默认 passed。

| 情况 | 内部草稿导出提案 | 可发布用途导出提案 |
|---|---|---|
| 核验 passed 且版本当前、全部确认/身份条件满足 | 允许，附证据和核验 | 允许；仍不自动平台发布 |
| pending | 用户明确确认“待核验草稿”后允许；标题/文件/正文带标识，必须包含原因、人工动作和来源 | 拒绝，返回待处理项 |
| rejected | 只允许诊断包/内部审阅草稿，显著带“已拒绝，不可发布”与完整错误；不能仅导出干净软文 | 拒绝 |
| 无核验、旧版本核验、内容/上游已失效 | 可查看历史；诊断包可明确标出版本及失效原因 | 拒绝，先对当前版本核验 |
| 未登录/跨用户 | 拒绝任何业务导出 | 拒绝 |

Frontend 禁止用“复制正文”绕过上述用途提示；Backend 对所有导出入口强制校验。草稿复制与下载语义一致。JSON/Markdown 都包含内容版本、完整型号、图片 media_id/来源身份、获取时间、核验结果/原因与人工动作。签名 URL 不持久导出为事实来源；图片用持久来源身份或授权代理引用，不能把密钥或本地路径写入导出。

## 7. 客户跟进建议（W5 边界）

输入为当前用户拥有的虚构 Lead、关联任务/成稿/核验、已有 FollowUp 记录及可选用户反馈。客户需求是用户输入，产品事实仅来自当前证据；不能推断客户已经到店、点击、满意、购买或同意联系。

输出建议动作、依据（用户给定需求/已记录事实/营销假设分开）、建议提问、拟沟通文案、可引用内容版本、待核验项。pending/rejected 或过期成稿只能建议补证据/核验/澄清，不建议发送为可发布内容。won/lost 不自动改变，联系方式/时间由用户确认；没有时间输入不凭空安排 next_follow_up_at。

用户“采用建议”与“记录已完成跟进”分开；前者不证明客户已收到。Backend 负责保存、幂等与隔离，Frontend 明确展示建议/计划/已发生记录。模块不发送消息、自动触达或自动完成成交。

## 8. 可观察验收与实施分工

| 场景 | 预期结果 | 主责 |
|---|---|---|
| 只输入 MateBook 14，无版本确认 | 返回线上候选，画像/内容调用被服务端阻止，用户可选择版本 | Workflow 规则；Coordinator IMA；Backend/Frontend 执行 |
| 无人群/场景/目标 | 草稿可保存；生成前逐项提示，不自动填入营销结论 | Backend + Frontend |
| 未确认画像或策略直接生成内容 | 服务端拒绝；不依赖按钮禁用 | Backend，Workflow 校验辅助 |
| 单独变人群 | 型号/证据保留；画像起失效；真实输出切入点改变 | Workflow + Backend，Frontend 展示 |
| 单独变平台 | 型号/画像确认保留；策略起失效；小红书卡片与公众号文章/图片数不同 | 同上 |
| 老生成请求执行时改简报/证据 | 完成后不能写入新当前版本；旧有效结果及历史不被覆盖 | Backend 实际竞态测试 |
| 仅刷新图片临时访问 URL | 不重生成营销正文，访问检查重新获取；不能宣称视觉已核验 | Coordinator + Backend + Frontend |
| 改标题、删除证据或图片拒绝 | 旧核验/导出资格立即失效，新版本再核验 | Backend + Workflow |
| 反馈修订引入虚构价格/跨型号素材 | W4 拒绝或要求补证据；代码错误不被模型“通过”覆盖 | Workflow 模块自测/真实 LLM 评估 |
| pending/rejected 走普通导出或复制 | 按冻结产品规则拦截/带标识；不能从不同入口绕过 | Backend + Frontend |
| 生成跟进建议后客户需求改变 | 建议标旧；采用前校验快照，不自动变成已发送记录 | Workflow + Backend + Frontend |

W0 后优先修复真实 IMA 空 URL 接缝并联调现有四函数；W4/W5 新签名先冻结再实现。真实模型质量必须单独做同平台换人群、同人群换平台的单变量评估；合成测试不替代营销效果验收。
