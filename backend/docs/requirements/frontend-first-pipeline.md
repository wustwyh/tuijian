# PR2：四项业务能力，先交付前端框架

## 当前最高优先级

用户明确要求：时间不足，先围绕四项功能细化整体任务管线、搭建完整前端框架，再通过后端逐段实现；停止以反复核对依赖/接口作为主要进展。
本需求覆盖旧“接口全部冻结后才能做页面”的调度安排；保留 PR1 的少输入、产品图片选项和一键生成。四角色职责不变，不创建 QA 或新的开发角色。
框架与真实接入是两种交付状态，分别验收，不能用框架可点击宣称真实业务已完成。

## 业务结构

主线：选择产品品类/明确型号 → A 客群自动调研 → C 营销运行策略 → D 平台广告/海报 → 核验与导出。
客户分支：B 客户需求卡 → 跟进记录与下一动作 → 可选带入 C/D → 将结果关联客户跟进。
客户分支可独立使用，不要求所有营销任务先建客户；通用营销方案也能一键完成。

“运行策略”在本项目指营销运营策略。产品大类用于筛选与客群分析；引用具体产品事实、图片、规格前必须确定型号/版本，不能把单型号能力泛化到全类产品。

| 功能 | 用户最少操作 | 系统任务管线 | 前端可见产物 |
|---|---|---|---|
| A 产品客群自动调研 | 选品类/产品，点击调研或一键生成 | 形成调研问题→检索已有可靠资料→提取产品事实/场景→分析匹配人群→比较痛点/动机/顾虑→推荐画像并标注依据/假设 | 2—3 张画像卡、推荐理由、需求/场景、来源与待核验项 |
| B 单客户需求与跟踪 | 选择已有客户或填一个称呼；需求标签点选 | 整理客户已知需求→列缺失信息/待问问题→匹配产品/方案→记录本次接触→生成下一动作与提醒时间 | 客户列表、需求卡、意向阶段、跟进时间线、下一步建议与关联内容 |
| C 产品营销运行策略 | 默认用推荐画像；可选带入客户 | 选目标→明确核心矛盾→匹配有证据卖点→定平台/内容角度→给出执行步骤、CTA、注意事项 | 策略摘要、核心卖点和论据、内容主题/执行步骤、行动建议、风险清单 |
| D 平台 AIGC 广告/海报 | 点选平台与广告/海报模板，或接受默认 | 生成标题/正文/图注/CTA→匹配真实产品图→模板排版→事实/型号/平台核验→导出 | 实际排版的广告卡片或海报预览、可编辑文案、引用与核验、下载/复制入口 |

A 的“调研”包括任务分解、资料检索、分析与证据追溯；当前先使用线上 IMA 和已有可用来源。没有市场统计/访谈/公开研究来源时，清楚区分“有来源发现”与“营销假设”，不声称做过全网调研或真实用户调查。扩展联网研究不是第一版 UI 的前置依赖。
B 首版轻量实现称呼、需求标签、阶段、跟进记录、下一动作/时间及关联任务；不用完整 CRM、自动消息推送或真实客户敏感信息导入阻塞交付。客户未提供的需求不能由模型伪造。
D 第一条真实闭环至少交付一个平台的一种实际排版模板（优先已有小红书能力）；原有其他平台按现有能力接续。海报不是只有 poster_brief 文本：必须看到排版成品，后续接通实际图片下载；未接通时按钮标明状态。首版 PNG 或 SVG 可由 Frontend 选最省事的可验证实现，并报告格式与限制，不再等待额外格式决策。

## 前端框架：五个业务入口

复用现有 React/Vite、登录和路由，不重建工程、不再限制必须压成四页。

1. **产品与总览**：品类筛选、产品图片卡片/版本、可选偏好、“一键生成营销方案”、历史方案。
2. **客群调研**：资料/分析进度、画像卡、推荐理由、来源/假设、选择或调整目标人群。
3. **客户跟进**：客户列表、客户详情、需求标签、阶段、跟进时间线、下一动作、关联策略/内容。
4. **营销策略**：产品/人群/客户上下文、策略摘要、卖点论据、执行步骤、CTA、生成内容入口。
5. **内容工坊**：平台/模板选项、文案编辑、真实排版预览、图片位置、核验说明、复制/下载与关联客户。

主线页面通过相同产品/方案上下文连接；一键模式自动推进，用户可随时查看各阶段结果。客户工作区独立导航，选择客户后可把需求带入策略与内容。
不要求营销员先填一张长表单；人群/场景/目标默认推荐，更多设置折叠。主页面需覆盖空、加载、成功、待接入/失败状态。

## 先框架、再真实接入

**M0：完整可点击框架，当前第一交付。**

- Frontend 先写上述五个入口与可操作控件、主要结果布局；第一交付必须能打开浏览器，能沿主线点击，也能进入客户分支。
- Frontend 可以自行定义模块内 view model 和 service adapter，并用明确的开发预览数据验证布局/交互；不等待新 HTTP 接口正式冻结。
- 开发预览必须独立、显著显示“框架预览·示例数据”，不得出现在正式接口成功路径，不伪造登录、保存或线上检索成功。已有真实产品图片可用于对应产品，缺图用中性占位。
- 正式模式依赖未接时显示真实待接入/错误，可用的现有功能继续可用。预览中的浏览器临时状态不能宣称真实持久化。
- Frontend 给 Backend 一份紧凑的 adapter 函数及输入输出样例即可；字段翻译在 adapter 完成，Backend 不必与页面模型逐字段同名。

**M1：接通一条真实主线。**

产品目录/图片 → 自动建任务/保存 → A 调研和画像 → C 策略 → D 一个平台的广告/海报 → 核验/导出。Backend 使用已有身份/SQLite/IMA/LLM 能力，Workflow 复用现有生成函数；每接通一段，前端替换相应预览适配。
缺密钥/外部服务时明确报告该段阻塞，不阻塞其他页面和独立功能。无需等待客户完整服务、全部平台或通用状态框架才接第一条主线。

**M2：客户分支与横向补齐。**

客户保存/需求标签/跟进记录 → Workflow 下一步建议 → 将客户需求带入策略/内容 → 关联生成结果。补齐平台切换、修订、失效与失败处理。M0 已包含这些页面，M2 接真实服务。

## 本批四角色任务

| 角色 | 立即做 | 下一次交付必须包含 | 不再等待 |
|---|---|---|---|
| Frontend / FF1 | 五入口、主线/客户分支、卡片/策略/实际广告海报布局、本地 adapter | 可打开地址、可点击路径、页面截图/检查、adapter 样例、哪些是真实/预览 | 所有新端点、错误枚举、版本字段全部冻结 |
| Workflow / WF1 | 四项能力的可调用输出，自动推荐初稿模式，客户建议及创意模板字段 | 函数/最小样例和模块验证；直接交给前端/后端接入 | 新一轮完整 W0 文档与四方确认 |
| Backend / BF1 | 接现有身份/存储，按页面依赖逐段接目录/图片与主线，再客户分支 | 已接通的一段真实能力与复现调用；下一段具体缺口 | 全部业务模型/重试预算/导出机制一次设计完 |
| Coordinator + IMA / CF1 | 保证可启动框架、提供真实产品图文、及时接收代码、处理实际阻塞 | 启动入口、集成的可见页面/功能；小批契约补齐 | 每个小字段预先走多轮批准 |

各角色先完成最小能演示的一段并自验，不用新增专门 QA，也不等待其他所有功能完成。次要优化、通用抽象、穷举测试和重复对账后移；身份隔离、凭证安全、来源真实性这些正在使用的路径仍须正确。

## 协作规则调整

- “本模块内部页面模型/函数/适配层”允许负责人直接决定并实现；不为它申请公共契约批准。
- 跨模块只约定当前一段所需的最少输入输出；可用具体函数/样例先衔接，Coordinator 随集成更新 API/类型，不以完整契约为前端框架门禁。
- 已发布公共接口保留兼容；会破坏消费者的改动必须及时通知，但不因此停止无关页面工作。
- 消息以“已交付入口、下一动作、具体阻塞”为主；一次提出可执行方案，避免纯讨论往返。收到通知回复自己的下一动作即可，不等全员确认。
- 独立会话不会被信箱自动唤醒；不活跃时用户粘贴 PR2 提醒。记录已发送与已接收，不能把发送当执行完成。

## 最小验收

- M0：五入口可见，主线与客户分支可点击，广告/海报有实际排版预览；零必填长文本；预览与真实状态清楚；可启动且浏览器无阻断错误。
- M1：一个明确型号、一组真实来源、一个平台，生成并保存画像/策略/创意、呈现核验；输出可按规则复制或下载；不能声称历史样例是实时结果。
- M2：一个虚构客户保存并重开、记录一次跟进、生成下一步建议、关联一份内容；客户数据隔离。
- 最终由用户评估四项功能与整体体验。现有实现保留，不 reset/clean 或覆盖其他会话的在途文件。
