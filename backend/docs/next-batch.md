## 管线与交付顺序

主线：选产品/品类 → 客群自动调研 → 营销运行策略 → 所选平台广告/海报 → 核验/导出。
客户分支：客户需求 → 跟进记录/下一动作 → 可选带入策略和内容 → 将结果关联跟进。

1. M0：先交付全部前端业务框架，包含客户分支及实际排版预览。模块内 view model/service adapter 可先实现；独立、清楚标识的开发预览允许使用示例，不混入正式运行链路。
2. M1：后端与 Workflow 逐段接通一个产品/一个平台的真实主线，每接一段替换对应适配；不等待客户全功能或所有契约。
3. M2：接通客户存储、跟进建议、关联内容，再补其他平台与修订/异常。

已有 API §8、模块实现与安全要求继续有效。具体新接口随集成补齐，禁止把“全部接口冻结”作为 UI 开工前置。产品事实/图片必须来自线上 IMA，未知项不补写；真实依赖阻塞不影响独立框架工作。
开发者自行验证，Coordinator 做最小集成检查，用户最终验收；无独立 QA。

## 回报方式

下一次回报要有可打开页面、实际函数或真实接口中的至少一项，以及已验证/未接通边界。不要只回报“依赖核对完成”。通过共享信箱发入口与下一动作，不等待全员逐轮批准。
只读取当前任务需要的角色包、PR2、自己的源码和最小上游样例，不扩大到仓库/知识库全量扫描。
