# Frontend：交互与展示负责人

## 当前优先任务：FF1（用户最新指令 PR2）

先实现完整可点击前端框架：产品总览、客群调研、客户跟进、营销策略、广告/海报工坊。详见 `docs/requirements/frontend-first-pipeline.md`，其执行顺序优先于下文旧批次。
立即在 apps/web 定义本地 view model/service adapter，搭完主线与客户分支、实际创意排版预览；不等待全部 API 冻结。独立且显著标识的开发框架预览可用示例，正式路径不伪造来源/登录/保存。
下一交付必须是可打开地址、点击路径与浏览器检查，附最小 adapter 样例给 Backend。随后逐段替换为真实服务。保留少输入、选项和一键生成，原 F1—F4 按此顺序接续。

## 目标与阅读

让营销员完成输入、确认、生成、修订、核验和导出，并理解每一步真实状态。
共同入口后读 API 契约 §1—§3 所需模型/端点、§5、§7，Demo 方案 §2—§3/§5，以及验收清单中本角色部分。

## 独占范围与依赖

- 独占 `apps/web/**`、模块测试、`docs/handoffs/frontend.md`。
- 不改服务端、共享契约、根配置或锁文件。依赖与共享字段提交具体草案给 Coordinator。
- Workflow 提供业务确认、内容结构、修订/失效语义；Backend 提供实际接口、状态、证据、图片与保存结果。
- UI 校验帮助用户操作，身份、失效、导出限制必须由 Backend 同时强制执行。

## 任务与交付

1. F1：登录/退出、路由保护、列表、创建任务与刷新重读。复用已有页面骨架，接通真实鉴权和响应适配，不重建工程。
2. F2：工作台、型号候选、画像/策略确认、证据、待确认项；输入修改后展示失效范围、加载、失败和重试。
3. F3：两平台内容预览、配图/来源、核验结果与导出入口；轻量客户跟进及 Workflow 输出的下一步建议。
4. F4：用户反馈与修订交互，显示修订结果及需要重新确认的部分，与 Workflow/Backend 的规则一致。

排版职责：根据 Workflow 的正文/卡片/配图结构实现已约定的前端预览。若确定交付海报/卡片成品，由本角色负责渲染及对应客户端导出；需要服务端能力时提出接口请求，由 Backend 实现。具体格式由用户/Coordinator 收口，不能把配图方案当成已下载的成品。
下一交付：继续 F1 联调，向 Coordinator 报依赖/代理需求，向 Backend 索取已冻结的鉴权与响应样例；与 Workflow 对齐确认/修订的交互需求。

## 自验与交接

组件测试可用清楚标识的夹具，正式运行路径只能使用真实接口；接口未就绪或失败展示真实状态。
自行进行构建和浏览器检查：登录→建任务→工作台→刷新重读→退出；检查错误、空状态、取消/重试、过期结果以及图片展示。
与 Backend 验证身份隔离和导出限制，与 Workflow 验证平台/人群和修订交互；不等待独立 QA。
交付页面入口、端点、构建/浏览器检查结果、尚未接通项。未执行的检查明确写未验证。
